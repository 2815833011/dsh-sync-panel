# dsh-sync-panel

在 DSH 里点按钮，把工作台配置推到 git；换台机器再点按钮拉回来。

这是 `../dsh-sync` 的图形前端。`dsh-sync` 负责「哪些文件算配置快照」，这个插件负责
「让你看见改了哪些、勾哪些、推上去、拉下来、推坏了能退回去」。

---

## 它解决什么

配置同步的麻烦从来不是 `git push`，而是这三件：

1. **看不见** —— 后台脚本推了还是没推、推了哪几个文件，全靠猜。
2. **不敢推** —— 一把梭 `git add -A` 会把临时文件、密钥、会话垃圾一起推上去。
3. **推坏了没法退** —— 两台机器各有一条历史，`reset` 是灾难，`revert` 又没人记得敲。

所以面板只有三件事：让你**逐文件勾选**、**当场看 diff**、**用 revert 回滚**。

## 装

已经装好。如果换机器要重装：

```bash
# 1. profile 的 package.json 加依赖
#    "dsh-sync-panel": "link:~/Documents/dsh-workspace/link-plugins/dsh-sync-panel"

# 2. 建目录联接（Windows 上 ln -s 需要开发者模式，junction 不需要）
cmd //c "mklink /J C:\Users\<你>\.dsh\profiles\desktop\node_modules\dsh-sync-panel E:\工作空间\DSH工作台改造\dsh-sync-panel"

# 3. 重启 DSH
```

**注意**：必须是 junction / 符号链接，不能是复制过去的一份。复制的话改源码不生效，
而且下次装别的插件时可能被 pnpm 覆盖掉。

## 用

重启后左侧图标栏多一个「同步」。

面板只有一屏，从上到下三块：**状态卡 → 变更卡 → 更多**。想深入就点「查看详情」，
进去是四个 tab（文件 / 历史 / 日志 / 设置），按「返回」回到主视图。

### 状态卡：一眼看出同步了没

| 元素 | 含义 |
| --- | --- |
| 仓库名 + 路径 | 当前同步的是哪个仓库。改路径在「设置」里。 |
| 分支徽标 | 当前分支。 |
| 状态徽标 | 一句话：`已是最新` / `N 个文件有改动` / `N 个提交没推上去` / `远端多 N 个提交` / `本地和远端都有新提交` / `解决冲突`。 |
| 上次同步 | 上次同步的**时间**、结果和提交号。从没同步过显示「还没同步过」。 |
| 大按钮 | 见下。 |

### 大按钮：按当前状态告诉你下一步做什么

只有一个按钮，避免「推送/拉取/回滚」并排摆着让人自己判断。判断顺序是：

1. 正在操作 → 按钮变灰，标签是「推送中…」之类。
2. 有冲突 → **解决冲突**（此时任何写操作都会失败，先解决）。
3. 远端有新提交 → **先拉取 N 个提交**（直接推几乎必被拒）。
4. 有勾选的文件 → **推送 N 个文件**。
5. 工作区干净但还欠推 → **推送 N 个提交**（上次提交成功、推送失败的补救口）。
6. 都没有 → **已是最新**（禁用）。

这段规则抽在 `client.js` 的 `primaryAction()` 里，有 6 个单测覆盖——
它是面板的主要信息来源，判错会让用户做错事。

### 变更卡

显示 `已选 / 共几个` 和一行文件名徽标（最多 6 个，多的显示 `+N`）。
逐文件勾选和看 diff 在详情页的「文件」tab 里。

### 更多

| 按钮 | 行为 |
| --- | --- |
| 历史 | 提交历史。点一行选为回滚目标，再点「回滚」。 |
| 日志 | 操作日志尾部 80 行，读 `~/.dsh/dsh-sync/log.txt`。 |
| 设置 | 改仓库路径、自动推送。 |
| 从本机导出 | 跑 `node bin/export.cjs --layer-only`，把本机 `~/.dsh` 刷新进快照仓库的 `layer/`。详见下节。 |

### 从本机导出（重要）

面板操作的是 `dsh-sync/layer/`，那是 `~/.dsh` 的**副本**。你改了技能、改了宪法，
副本不会自己变。完整链路是两段：

```
~/.dsh  --export.cjs-->  dsh-sync/layer  --面板推送-->  git
~/.dsh  <--apply.cjs--   dsh-sync/layer  <--面板拉取--  git
```

**面板只负责中间那段。** 所以流程是：改了配置 → 先点「从本机导出」→ 再推送。

这个按钮不是可选的便利功能——不点的直接后果是推上去旧快照。真实发生过：
`layer/AGENTS.md` 还是 1740 字的老宪法，而 `~/.dsh/AGENTS.md` 已经改成 535 字了。

`status` 会返回 `canExport`，仓库里没有 `bin/export.cjs` 时按钮直接不显示
（面板可以指向任意 git 仓库，别的仓库没有这个脚本）。

### 冲突怎么办

拉取撞上冲突后，「解决冲突」按钮会亮。点开是三路对比：每一块冲突单独选「用我的」或
「用远端的」，祖先段默认收起可展开。**所有块都选完才能提交**——漏一处就不写文件，
免得半个冲突标记被提交上去。

取消就去 `git merge --abort` 也不对：这时合并还在进行中，取消只是关页面。
真要放弃，命令行 `git merge --abort`。

### 自动推送

在「设置」tab 里。打开后两种模式：

- **安静后推**（默认）：改动停下手 N 秒才推。适合「写到一半别打断」。
- **定时推**：每隔 N 分钟推一次。适合「我就是要它一直在传」。

三条铁律：

- 有冲突待解决时**绝不**自动推 —— 那时候推上去的是带 `<<<<<<<` 的文件。
- 面板上正在跑别的操作时跳过这一轮，不排队。
- 连续失败 3 次自停。断网一夜不该给你留几千行日志和一个「还在转」的面板。

自动推送只推**勾选过**的文件。没勾过的当作你没答应。

## 状态存哪

```
~/.dsh/dsh-sync/
  repo.json        上次用的仓库目录（重启后自动恢复，见下）
  selection.json   勾选记忆
  last.json        上次操作记录（含仓库路径，用于重启后恢复定时器）
  auto.json        自动推送设置与失败计数
  log.txt          全部操作日志，一行一次
```

这些**不进 git**。它们是本机状态，推上去会跟另一台机器打架。

可用 `DSH_SYNC_STATE_DIR` 环境变量改目录（测试用）。

**为什么仓库路径非得存在后端**：DSH 每次重启 web 端口都会变
（1317 → 4718 → 8591 → 7345 …），而 `localStorage` 按 origin 隔离，
端口一变就等于换了个站点。第一版把路径只记在 `localStorage`，结果每次
重启都退回到「先选一个仓库目录」。现在双写：`localStorage` 当快路径，
后端 `repo.json` 当真相，前端启动时本地为空就向 `/repo` 问一次。

## 出问题看哪

| 现象 | 先查 |
| --- | --- |
| 面板不出现 | DSH 重启了没有；`profiles/desktop/package.json` 的 bundles 里有没有 `dsh-sync-panel` |
| 按钮点了没反应 | 打开操作日志；再看 `log.txt` |
| 一直报「已有同步任务正在执行」 | 上一次操作中途崩了，锁没释放。重启 DSH。 |
| 自动推送不动 | 看卡片是不是显示「连续失败 N 次」；再确认有**勾选**的改动 |
| 推送成功但 GitHub 上没有 | 看有没有 push 权限；`git remote -v` 对不对 |
| 提示「已在本地提交，但没有推送到远端」 | 这是**半成功**，不是失败。提交已在本地，远端没有。看日志里的 git stderr，多为凭据或网络。修好后**再点一次推送**即可——面板会显示「未推送 N」徽标，推送按钮保持可点，第二次会把欠推的提交推上去。 |

## 安全边界

- 13 条路由全部**只认 loopback**（`127.0.0.1` / `::1` / `::ffff:127.0.0.1`）。
- 必须带 `x-dsh-sync-panel: 1` 头。跨站表单设不了自定义头，所以这挡得住 CSRF。
- 只接受 POST。`<img src>` 那种 GET 触发不了。
- 所有操作共用一把锁。两次点击同时驱动 git 是丢数据的经典方式，第二次直接 409。
- 文件路径一律过 `isInsideRepo`。`--` 后面的 `..\..\.ssh\id_rsa` 是**合法 git 参数**，
  不校验就等于把任意文件推上去。

## 测试

```bash
cd dsh-sync-panel

# 逐文件跑（node --test 在沙箱里会 spawn EPERM）
for f in test/*.test.mjs; do node "$f"; done
```

138 个用例。涉及真实 git 子进程的用例需要放宽文件沙箱（`danger-full-access`），
因为 git 建管道会被工作区写权限拒掉。

**还有一朵必须真跑才能抓到的坑**，见 `test/e2e-real-repo.mjs`：

```bash
node test/e2e-real-repo.mjs "E:/工作空间/DSH工作台改造/dsh-sync"
```

假 git 的单测能证明调用序列对，证明不了真 git 会成功。这个脚本跑之前，
全部单测全绿，真实仓库却卡在「本地有提交、远端没有」——因为 `main` 从来没设
upstream，而假 git 把这条分支圆过去了。**凡是涉及外部系统状态的改动，最后
一定要在真东西上跑一遍。**

| 文件 | 覆盖 |
| --- | --- |
| `git.test.mjs` | 参数数组化、中文+空格路径、porcelain 解析 |

## 和 `dsh-sync` 的分工

```
dsh-sync/bin/*.cjs     命令行：一次性安装包、配置层导出导入、会话增量合并
dsh-sync-panel/        面板：日常的看改了什么、勾选、推送、拉取、回滚
```

首次跨机器搬家还是用 `dsh-sync` 的 `make-package.cjs`（自带凭据和会话，约 24MB）。
之后日常用面板。

**没做的**：面板不碰会话文件。会话 24MB 且变化频繁，进 git 只会把仓库撑爆。
会话的跨机器合并仍走 `dsh-sync/bin/apply.cjs --sessions`。
